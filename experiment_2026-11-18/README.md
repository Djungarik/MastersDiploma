# Перевірки 18.11.2026: гучність, звукові переходи, інтервали аналізу

Матеріали до підрозділів 5.5 і 6.3 та додатка В кваліфікаційної роботи.

## Середовище

- Ноутбук: Intel Core i5-10210U, 8 ГБ ОЗП, Windows 11 Home 10.0.26300.
- Браузер: Google Chrome 157.0.8103.79, режим без графічного вікна. Керування браузером: playwright-core 1.48.
- Сервер: `GROQ_MODEL=qwen/qwen3.8-27b`, гілка `thesis-review-fixes`.

## Файли

| Файл | Призначення |
|---|---|
| `audio_tap.js` | Підключається до сторінки до її скриптів. Відгалужує сигнал, що йде на `AudioContext.destination`, і кожні 10 мс зберігає RMS, пік і найбільший перепад між сусідніми відліками. |
| `audio_test.mjs` | Через інтерфейс змінює гучність (повзунок Volume), п'ять разів викликає `audioEngine.crossfadeTo` і виконує ручний вибір настрою. Паралельно кожні 5 мс записує `masterGain.gain.value`. |
| `audio_analyze.py` | Аналізує запис: стрибки коефіцієнта підсилення, тривалість згасання й наростання, паузу між ними, рівень виходу. |
| `make_timeline.py` | Складає доріжку для фейкового мікрофона з 20 сцен (`scenes.json`, озвучення `tts.ps1`). |
| `e2e3.mjs` | Наскрізний прогін із заданим інтервалом аналізу та записом звуку й коефіцієнта підсилення. |
| `analyze_metrics.py` | Однакові часові показники для всіх прогонів 10.11 і 18.11: час транскрибування й аналізу, затримка до початку зміни звуку, повний час реакції після завершення репліки. Результат записується в `metrics_summary.json`. |
| `analyze_int.py` | Аналізує прогони: результати по фрагментах і сценах, затримки, переходи. |
| `runs/` | Журнали (`log.json`), підсумки та знімки екрана. |

Прогін `audio_before` виконано до виправлення дефектів BUG-06…BUG-08, `audio_after` — після їх виправлення. Прогін `audio_final` виконано на остаточній збірці, після виправлення BUG-09. Прогін `audio_r3` (22.11.2026) виконано після того, як `crossfadeTo` став повертати обіцянку, а переходи — виконуватися послідовно (BUG-10). У ньому виміряно повну тривалість переходу та перевірено дві команди поспіль. Прогони `int10`, `int30` і `int60` виконано до виправлення BUG-09, яке знайдено саме в `int30`; прогін `int20` — після нього. Підсумки зведено у файлах `int_summary.txt` та `int_rows.json`.

## Відтворення

```
cd experiment_2026-11-18
powershell -File tts.ps1                  # озвучення сцен у wav\sceneNN.wav (голос Microsoft Hazel Desktop)
python make_timeline.py 10                # те саме для 30 і 60 с; для 20 с використано timeline.wav з experiment_2026-11-10
node e2e3.mjs int10 420 timeline_10.wav 10
node e2e3.mjs int30 620 timeline_30.wav 30
node e2e3.mjs int60 1220 timeline_60.wav 60
python analyze_int.py int10 int20 int30 int60
node audio_test.mjs audio_after
python audio_analyze.py audio_after
```

Перед прогоном мають бути запущені сервер (`uvicorn app.main:app --port 8000`) і клієнт (`npx vite --port 3000`).
